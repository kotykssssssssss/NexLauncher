# Modrinth в NexLauncher

**Modrinth** в sidebar открывает два независимых каталога: **Modpacks** и **Mods**.
Modpacks создаёт новую сборку. В Mods выбери существующий Fabric, Forge или NeoForge
instance в поле **Установить в**. Также доступен путь **Играть → Моды**.
Minecraft и loader подставляются автоматически; Vanilla не получает loader-specific JAR.

Каталог и страница проекта занимают всю рабочую область после sidebar с обычными
отступами. В широком окне фильтры находятся слева; в узком — в раскрывающемся блоке
над результатами. Карточки горизонтальные, прокручиваются внутри доступной высоты.
Это отдельная страница, не popup и не ограниченная по ширине центральная панель.

Фильтры Modpacks: Minecraft release version, Fabric/Forge/NeoForge, категория,
окружение (все / только клиент / клиент и сервер / одиночная игра).
В Mods Minecraft и loader закреплены за выбранным instance; доступны категория
и окружение. Названия категорий приходят из `/tag/category`, версии Minecraft —
из `/tag/game_version`. Сортировка: релевантность, загрузки, недавно обновлённые,
новые проекты (`index` официального search API). Неподдерживаемые фильтры не показаны.
Если справочник недоступен, поиск работает с имеющимися фильтрами; его можно обновить.
Выбранные Minecraft/loader фильтры Modpacks также ограничивают версии на details.

Поиск показывает иконку (если доступна), название, описание, автора из API,
downloads и совместимость. Нажми любую часть карточки, включая название или
иконку: откроется отдельная страница проекта. Кнопки предыдущей/следующей страницы
листают по 20 результатов. Поиск задерживается на 400 мс после ввода; предыдущий
отменяется. Поиск и загрузку details можно отменить отдельной кнопкой.

## Страница проекта

Путь для мода: **Mods → instance → поиск → карточка → версия → Установить мод… →
план dependencies → Подтвердить установку**. Вкладка **Установленные** показывает
только управляемые NexLauncher моды. Их карточки открывают ту же страницу без поиска.
**К результатам** сохраняет список, запрос, фильтры, сортировку, страницу и scroll.
Mods и Modpacks имеют отдельные параметры поиска на время работы приложения;
переключение сохраняет выбранный instance. После смены instance пагинация сбрасывается.
Состояние поиска не записывается в settings при закрытии приложения.

На странице доступны название, иконка, краткое и полное описание, тип проекта,
downloads, категории, даты публикации/обновления, окружение, license ID,
все заявленные Minecraft versions и loaders. Версии Minecraft
раскрываются отдельно, чтобы большой список не занимал весь экран. Author из
search и публичные участники команды из `/project/{id}/members` подписаны отдельно.
Если API сообщает organization ID, есть ссылка на организацию; её название не
угадывается из ID (в текущем документированном v2 нет отдельного organization-name
endpoint). Ошибка получения команды/иконки не блокирует описание и установку.

Для текущей сборки показаны установленная через NexLauncher версия и наличие
более новой совместимой версии по `date_published`. Release/beta/alpha не
скрываются: номер и тип версии видны в выборе. Обновление выполняется только
после явного выбора и проверки плана. Ручные моды и исходные JAR modpack не
определяются как управляемая установка. Для modpack явно указано создание
отдельной сборки; текущая сборка никогда не используется как цель pack installation.

Список доступных версий фильтруется по точному Minecraft, loader и клиентскому
environment. После выбора compatibility проверяется снова при построении плана
и непосредственно перед установкой. Пустой список и ошибки API не включают кнопку
установки. Незавершённые запросы при уходе со страницы отменяются; устаревший ответ
не может подменить другой проект.

### Полное описание и безопасное форматирование

Описание берётся из официального поля `body`, а не из HTML сайта. Поддерживаются:

- заголовки `#`–`######`, абзацы и переводы строк;
- простые списки `-`, `+`, `*`, `1.`/`1)` (один уровень, отображаются маркерами);
- цитаты `> `, блоки кода с тройными backticks или `~~~`;
- `**жирный**`, `*курсив*`, inline code в backticks;
- `[текст](https://example.org)` и `![alt](https://example.org/image.png)`.

Изображения представлены ссылкой «Изображение: alt» и автоматически не скачиваются.
HTML, scripts, iframe, таблицы и неподдерживаемая разметка остаются текстом; они
не исполняются и не влияют на UI. Нет WebView, JavaScript, импортируемого CSS,
произвольного XAML или вложенного active content. Вложенное inline-форматирование,
reference links, URL с Markdown title/вложенными скобками не поддерживаются.
Разбор выполняется вне UI-потока; отображение использует native Avalonia controls.

Ограничения для слишком больших описаний: 262 144 символа, 512 блоков, 4096 spans.
При превышении отображается явное объяснение и остаётся ссылка на полную страницу
проекта. Обычные описания не обрезаются на прежних 10 000 символах.

Ссылки из описания, source/wiki/issues/Discord, лицензии и donation URLs открываются
только по клику. Разрешены абсолютные HTTP/HTTPS URL без credentials, localhost,
обратных слешей и управляющих символов. `file:`, `javascript:`, `data:` и shell
protocols отвергаются. URL виден в tooltip, у полезных ссылок также показан host.
Внешние страницы открывает системный браузер, не встроенное окно приложения.

## Моды и dependencies

1. Выбери конкретную версию и нажми **Установить мод…** (либо **Обновить / сменить версию…**).
2. Просмотри список, затем **Подтвердить установку**. План пересчитывается перед записью.
3. Общий progress и кнопка отмены находятся в нижней части главного окна.

Проверяется точный Minecraft, loader и client environment конкретной версии.
Новые API environment поддерживаются; для старого ответа без environment
используется project client_side. `unknown` и server-only не принимаются.

| Dependency | Поведение |
| --- | --- |
| required | Точная version ID либо совместимая версия project ID; добавляется в план и устанавливается |
| optional | Показывается в плане; не устанавливается автоматически. Найди и добавь отдельно по желанию |
| embedded | Показывается в плане, повторно не скачивается |
| incompatible | Конфликт с управляемыми установленными/планируемыми версиями останавливает установку |

Циклы обходятся один раз. Два разных обязательных version ID одного проекта
останавливают установку. Проверяются и зависимости уже установленных управляемых
модов, поэтому update не должен нарушить их pinned requirement. Максимум 256
управляемых проектов. Нет совместимой required dependency или её невозможно
идентифицировать через API — понятная ошибка без записи файлов.

Используется основной JAR версии. Версии с обязательным отдельным resource pack
отклоняются с объяснением; sources/dev/javadoc/signature не устанавливаются как мод.
Это не решатель произвольных ограничений внутри `fabric.mod.json`/`mods.toml`:
он использует объявленные Modrinth dependencies. Ошибки metadata автора могут
потребовать ручного подбора версий.

## Управление и ручные моды

В «Моды этой сборки» видны title, текущая версия и признак dependency.
**Проверить обновление** ищет более новую совместимую версию и открывает обычный
выбор версии/план. Update требует явной установки. Удаление shared required
dependency блокируется, пока установлен зависящий проект. При удалении главного
мода dependencies сохраняются; ненужные можно удалить отдельно.

`game/.nexlauncher/mods.json` (format 1) хранит устойчивые project/version IDs,
имя установленного JAR, hashes, dependencies и признак явной установки.
Slugs не используются как постоянные идентификаторы.

Ручные JAR и исходные файлы modpack не выдаются за установленные отдельно через
NexLauncher. Их нельзя удалить этой кнопкой. Совпадение имени с ручным файлом
блокирует запись; изменённый пользователем управляемый JAR тоже не перезаписывается
и не удаляется. Launcher проверяет конфликты только известных управляемых модов;
совместимость ручных JAR и компонентов modpack нужно проверить самостоятельно.

## Загрузка, целостность, восстановление

Файлы скачиваются в `.part` с ограничением размера; предоставленные SHA-512/SHA-1
проверяются до rename. Моды готовятся в `.nexlauncher/.nex-stage-*`. Замена файлов
и metadata имеет rollback; после начала короткого commit отмена завершается
после согласованной записи. Повреждённый download не становится установленным JAR.

Перед заменой записываются `transaction.json`, `before.json` и backup старых JAR.
При обычной ошибке файлы возвращаются. Если Windows/процесс аварийно завершился
посреди commit, journal блокирует новые операции с модами **и запуск игры**.
Автоматического crash recovery пока нет. Для ручного восстановления:

1. Закрой NexLauncher, сделай копию всей папки игры.
2. Открой `.nexlauncher/transaction.json`; `Stage` указывает staging, `Add` и
   `Remove` — файлы этой операции. Не удаляй остальные JAR.
3. Верни `backup` из указанного staging в `mods`. Удали только добавленные этой
   операцией JAR, которых нет в `before.json`; сохрани ручные изменения отдельно.
4. Верни `before.json` на место `.nexlauncher/mods.json`, затем убери journal.
5. Перезапусти launcher и проверь список. Staging удали лишь после восстановления.

Если metadata повреждена, её оригинал сохраняется. Не заменяй её пустым JSON:
это потеряет сведения о владении файлами.

## Modpacks (.mrpack)

В sidebar: **Modrinth → карточка → details → version → название → Установить**.
Папка — текущий Instances directory из настроек. Имя не превращается в путь.
Optional client files исключены по умолчанию; checkbox явно включает **все**
optional-файлы выбранного pack. Выбор каждого optional-файла отдельно пока отсутствует.

Читается ZIP, `modrinth.index.json`, formatVersion 1, game minecraft, dependencies,
SHA-1/SHA-512, размеры и env. Server-only files не скачиваются. Сначала применяется
`overrides`, затем `client-overrides`; `server-overrides` пропускается. Лоадер
устанавливается тем же независимым backend, затем CmlLib проверяет игру.
Instance регистрируется только после успеха всех стадий. Pack project/version IDs
и список контента сохраняются в `game/.nexlauncher/pack.json` (format 1).

Ссылки берутся из manifest, а не из HTML. Allowlist: `cdn.modrinth.com`, `github.com`,
`raw.githubusercontent.com`, `gitlab.com`; для GitHub redirects — также
`release-assets.githubusercontent.com` и `objects.githubusercontent.com`. Только
HTTPS/443 без userinfo; до 5 redirects с проверкой каждого адреса. Другие download
hosts требуют осознанного добавления в код; fallback на случайное зеркало отсутствует.

Безопасные ограничения: до 20 000 ZIP entries, до 512 МБ на распакованный файл,
4 ГБ overrides и 8 ГБ downloads в manifest. Запрещены traversal, duplicate/case
collisions, symlinks, scripts/executables, запись в служебные папки launcher,
versions/libraries/runtime/assets/natives. Некоторые packs с собственными scripts
или заменой runtime поэтому намеренно отклоняются. Quilt и неизвестные loaders
отклоняются, а не заменяются Vanilla. Экспорт/публикация, обновление целого modpack,
автоматическое управление отдельными исходными модами pack и локальный ZIP-import
сейчас не реализованы.

## HTTP и правила сервиса

Официальный публичный API v2; PAT/Modrinth login не нужен и не добавлен.
Общий `LauncherHttp` переиспользует HttpClient, не отправляет cookies или account
credentials. Каждый запрос получает:

    NexLauncher/0.1.0-alpha (github.com/kotykssssssssss/NexLauncher)

Номер берётся из assembly release metadata и обновляется вместе с версией приложения.

Учитываются `X-Ratelimit-Remaining`, `X-Ratelimit-Reset`, `Retry-After`.
GET получает не более 3 попыток на 429/5xx; долгий лимит предлагает повторить позже.
Metadata timeout 40 секунд, file download 15 минут. Небольшой кеш metadata —
до 3 минут и 128 ключей; учитываются `Cache-Control: no-store/no-cache/private`,
`max-age` и `Age`. Конкретная version перед установкой запрашивается заново.
Иконки ограничены 2 МБ, декодируются вне UI; их ошибка не блокирует установку.
HTTP ошибки/невалидный JSON показываются коротко, диагностика попадает в launcher log.

Проверены Terms, Content Rules, API docs и официальная mrpack specification
27 сентября 2026. Используются только разрешённые публичные API/download ссылки,
без scraping, обхода access controls, переупаковки или распространения чужих JAR.
Присутствуют текстовая attribution Modrinth, ссылки на проект и авторов, license ID.
Название используется для обозначения источника; логотипы Modrinth не копируются,
партнёрство/одобрение не заявляется. Это не выдаёт лицензии на повторную публикацию
модов: права и лицензии авторов сохраняются. Перед распространением производной
сборки нужно отдельно проверить permissions. NexLauncher ничего не публикует.
