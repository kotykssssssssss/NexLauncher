# Папки и сохранение сборок

**Настройки → Папка сборок → Выбрать папку…** открывает системный folder picker.
Можно выбрать локальную папку на доступном диске, например `D:\Games\NexLauncher`
или `E:\Minecraft`. Проверяются полный путь, доступность диска и пробная запись.
Пробный файл удаляется при закрытии, пользовательские файлы не изменяются.

Стандартная папка остаётся `%LOCALAPPDATA%\NexLauncher\instances`.
Изменение настройки влияет **только на новые сборки**. Существующие не переносятся
и продолжают использовать сохранённый абсолютный путь. Пробелы и Unicode допустимы.
Недоступный диск вызывает ошибку; launcher не подменяет его другой папкой.

## Структура

    <выбранная папка>/
      <instance-guid>/
        game/
          versions/ libraries/ assets/ runtime/
          mods/ config/ saves/
          .nexlauncher-installed
          .nexlauncher/
            mods.json
            pack.json

Папка игры всегда имеет структуру `<root>/<guid>/game`, имя сборки не используется
как путь. Root хранится в `settings.json: InstancesDirectory`, а у каждой сборки —
свой `GameDirectory`. Account metadata, DPAPI vault, launcher log и Quick CSS
остаются в прежней папке данных NexLauncher.

## Совместимость со старыми настройками

Настройки и instance имеют `FormatVersion = 2`. Старые записи без полей загрузчика
загружаются как Vanilla. Отсутствующий GameDirectory вычисляется из **старого
стандартного пути**, даже если новый root уже выбран. При следующем сохранении
записываются явные пути и новая версия формата. Исходная версия Minecraft, ID,
Java/RAM и выбранная сборка сохраняются. Форматы аккаунтов и DPAPI не менялись.

Неизвестный будущий формат и повреждённый JSON не перезаписываются пустым файлом:
показывается ошибка с путём. Настройки и metadata записываются через временный
файл на том же томе с финальным rename. Резервную копию важных миров пользователь
по-прежнему делает отдельно.

## Безопасность и ограничения

- Manifest не может использовать `..`, абсолютный путь, ADS, Windows device names,
  неоднозначные trailing dots/spaces или выйти за пределы instance.
- Junction/symlink и UNC/network paths в управляемой папке не поддерживаются.
- Modpack собирается в собственной `.nex-stage-*` папке выбранного root. После
  проверки игры, loader и файлов выполняется rename в новый GUID и сохранение
  конфигурации. При ошибке публикации папка возвращается в staging и очищается.
- Launcher удаляет только свои staging-папки и проверенные управляемые JAR.
  Неизвестные файлы и пользовательские папки не очищаются.
- Выбор root не проверяет заранее суммарное свободное место для всех будущих
  загрузок. Ошибка записи останавливает операцию; modpack не становится установленным.
- Для старых сборок недоступный диск нужно подключить заново. Автоматический
  перенос, объединение папок, shared library cache и UI удаления instance не добавлены.
- Принудительное завершение процесса/отключение питания может оставить staging.
  Он не регистрируется как установленная сборка. Не удаляй его во время установки;
  после закрытия launcher можно сохранить журнал и удалить только этот staging вручную.

Журнал восстановления отдельных модов описан в [MODRINTH.md](MODRINTH.md).

## Скины

Local Skin хранится отдельно от игр в `%LOCALAPPDATA%\NexLauncher\skins\<hash(type:id)>`:
managed PNG и атомарная metadata версии 1 с моделью и SHA256. Исходный путь импорта
не сохраняется; новый instances root не перемещает skin. Отсутствие этой папки
не требует migration аккаунтов. Corrupt metadata сохраняется для диагностики.
Microsoft-скин хранится в самом Minecraft-аккаунте, токены остаются только в DPAPI
vault. Installer/uninstall не удаляет папку skins. См. [SKINS.md](SKINS.md).

## Installer, Portable и обновления

Installer ставит binaries в `%LOCALAPPDATA%\Programs\NexLauncher` для текущего
пользователя без администратора. Данные по-прежнему находятся в
`%LOCALAPPDATA%\NexLauncher`; custom instances остаются на своих дисках.
Installer не разрешает выбрать стандартную папку данных как installation directory.
Не выбирай папку существующей игры для установки приложения.

Portable использует ту же папку данных: это запуск без установки, а не изолированный
USB-профиль. Не запускай несколько копий NexLauncher одновременно. Перенос одного EXE
не переносит сборки или аккаунты; DPAPI vault привязан к текущему Windows-пользователю.

Setup/uninstall владеют только файлами дистрибутива, ярлыками и uninstall registration.
Настройки, аккаунты, CSS и игровые файлы при update/reinstall/uninstall сохраняются.
Portable обновляется заменой application files после закрытия launcher.
Форматы settings/accounts в релизном этапе не менялись. Подробнее: [RELEASE.md](RELEASE.md).

## Export / Import

Переносимый `.nexpack` создаётся в явно выбранном пользователем месте. Import создаёт
НОВУЮ сборку в текущей папке instances с новым ID, используя staging на том же диске.
Старые instances остаются на своих путях; это не команда перемещения или замены.
Аккаунты, Java path автора и launcher settings не экспортируются. RAM переносится,
Java выбирается автоматически. Подробности: [INSTANCE_TRANSFER.md](INSTANCE_TRANSFER.md).
