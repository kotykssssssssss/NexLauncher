# Библиотека скинов

**Скины** в sidebar открывает нативный экран NexLauncher, без WebView.
В этом этапе реально подключён источник **Моя библиотека**: PNG, которые пользователь
явно импортировал на этом компьютере. Это не копия онлайн-библиотеки NameMC и не
поиск по миллионам чужих скинов.

## Использование

1. Нажми **Импорт PNG…** и выбери файл. Аккаунт для этого не нужен.
2. Проверь большой preview. Перетаскивание поворачивает игрока, колесо меняет масштаб.
3. Выбери **Classic / Steve** или **Slim / Alex**. Для современного 64×64 PNG модель
   выбирается пользователем; по пикселям она не угадывается. Нажми **Сохранить модель**,
   чтобы сохранить выбор в библиотеке. Legacy 64×32 преобразуется в Classic 64×64;
   вариант Slim для него не сохраняется.
4. **Сохранить PNG…** открывает системный Save File dialog с подтверждением замены.
   Это экспорт проверенного PNG, а не новая сетевая загрузка.
5. Выбери сохранённый аккаунт и нажми **В Skin Manager →**. Откроются настройки
   аккаунтов с черновиком PNG и выбранной моделью. Активный аккаунт запуска не меняется.
6. Только отдельная кнопка **Применить к Minecraft-аккаунту** изменяет Microsoft skin.
   Для Local кнопка **Сохранить Local Skin** сохраняет скин только в NexLauncher:
   [ограничения и видимость Local Skin](SKINS.md).

Карточка целиком открывает details; на ней также есть экспорт PNG.
Поиск по названию работает с паузой 350 мс, без сетевых запросов. Название берётся
из имени импортированного файла, максимум 80 символов. Автор PNG неизвестен и не
выдумывается. Страницы содержат по 24 записи. Возврат из details сохраняет запрос,
текущую страницу и позицию списка в пределах текущего запуска.

Удаление из библиотеки требует подтверждения. Оно не удаляет исходный файл,
применённые скины аккаунтов, mods или данные instances. Изменённые/неизвестные файлы
в managed папке не удаляются как принадлежащие библиотеке.

## Онлайн-источники: что не реализовано

В блоке **Где найти PNG для импорта** находятся обычные внешние ссылки на
[NameMC](https://namemc.com/), [SkinMC](https://skinmc.net/) и [MineSkin](https://mineskin.org/).
Скачивание на этих сайтах выполняется самим пользователем, с соблюдением правил
сервиса и прав автора. NexLauncher не объявляется их официальным партнёром.

На 4 октября 2026 года из рабочего окружения не удалось прочитать актуальные API
documentation и условия использования этих сервисов: веб-инструмент недоступен,
прямые запросы завершаются DNS-ошибками. Это **не доказательство отсутствия API**.
Наличие подходящего разрешённого API, размер библиотеки, лимиты, API keys, endpoints
и attribution requirements остаются непроверенными.

Поэтому в приложении нет автоматического онлайн-поиска, trending/recent, remote
skin download, HTML scraper, неизвестных endpoints или anti-bot workaround.
Локальные результаты не выдаются за результаты сторонних сервисов. Внешние
ссылки открывают только фиксированные главные страницы; account tokens, ник,
идентификаторы устройства и данные Local аккаунта к ним не добавляются.

## Архитектура

- `ISkinCatalogSource` описывает источник: его имя, поиск страниц и чтение текстуры.
  ViewModel не знает HTTP endpoints. `SkinLibrary` — фактически работающая локальная
  реализация интерфейса, без сетевой зависимости и без account credentials.
- `SkinCatalogItem`, `SkinCatalogPage`, `SkinCatalogTexture` — общие модели каталога.
- `SkinCatalogPreviewCache` вызывает уже существующий `SkinPreviewRenderer`.
  Details использует тот же `SkinPreview`, что Skin Manager; второго renderer нет.
- `SkinPngExport` заново проверяет PNG и пишет temporary file → atomic replacement.
- `SkinManagerViewModel.PrepareDraftAsync` проверяет переданную текстуру и готовит
  черновик. Account mutation остаётся в существующем `ISkinService` pipeline.

Будущий онлайн-provider должен пройти отдельную проверку официальных API/terms.
Нельзя просто добавить произвольный URL в ViewModel. Требуются проверка PNG/content
type, ограничение ответа, HTTPS/host validation, timeout, cancellation, rate-limit
handling, bounded cache и tests с fake HTTP. Неработающий online backend здесь не
создаётся.

## Хранение, cache и безопасность

`%LOCALAPPDATA%\NexLauncher\skin-library\<guid>\`:

- `skin.json` — `FormatVersion=1`, ID, название, Classic/Slim, legacy flag,
  SHA256 и время импорта. Исходный абсолютный путь и account data отсутствуют.
- `skin.png` — очищенный PNG 64×64, проверенный существующим `SkinValidator`:
  signature, dimensions, CRC, full decode, максимум 256 КиБ; APNG отвергается.

Новая запись сначала полностью создаётся в собственной staging папке, затем
атомарно переносится в готовую папку. Отмена не публикует недописанную запись.
Metadata обновляется через существующий `AtomicJson`. При чтении проверяются ID,
format version, model, размер и hash. Повреждённая metadata не затирается; соседние
записи остаются доступны с диагностикой. Повреждённый PNG не передаётся в Skin Manager.
Path traversal и symlink/junction в managed storage отвергаются.

Максимум 256 сохранённых записей; identical PNG/model/legacy импорт повторно
использует проверенную запись. При достижении лимита предлагается удалить запись,
а не автоматически стирать пользовательские скины. Skin files переживают restart,
обновление/uninstall вместе с прочими user data и не зависят от папки instances.
Каталог не переносит уже сохранённые account skins автоматически; их storage не менялся.

Cache миниатюр — только в памяти процесса: до 32 записей, срок пять минут,
192×192 PNG. Cache key — SHA256 PNG + модель; выдаются копии bytes.
Этот cache не переживает restart и не является папкой с бесконечными downloads.
Его eviction никогда не удаляет library/account skins.
Файлы staging после внезапного завершения питания и изменённые orphan files
сохраняются вне списка; разбирать их следует после закрытия приложения и backup.

## Quick CSS

- `#skin-catalog` — `Grid`: фон, opacity, margin; ограничения обычных панелей.
- `.skin-card` — `Button`: обычные button properties, `:hover` / `:disabled`.
- `#skin-details` — `Border`: свойства карточек и рамки.

Общие `button`, `text`, `.caption`, `textbox`, `combobox` остаются доступны.
Theme не получает доступ к PNG storage, account services или внешним запросам.

## Проверить вручную

- Импортировать настоящий PNG 64×64, выбрать обе модели, повернуть/увеличить preview.
- Проверить legacy 64×32, повреждённый PNG, неверный формат и отмену picker.
- Экспортировать PNG; проверить overwrite confirmation и путь с Unicode/пробелами.
- Перезапустить launcher после удаления исходного импортированного файла.
- Передать скин в Local и Microsoft Skin Manager; проверить выбранный аккаунт,
  черновик до Apply и реальное Microsoft изменение только после явного применения.
- Удалить запись и убедиться, что сохранённый account skin остался.
- Проверить сетку, details, Back, Quick CSS, DPI 125–200% и разные размеры окна.
- Проверить внешние ссылки; онлайн-поиск внутри launcher пока отсутствует.
## Результат проверки этой реализации

4 октября 2026 года:

- Debug и Release: успешно, 0 compiler warnings / 0 errors.
- Весь regression suite: **654 checks**, включая **63 новых** проверки библиотеки,
  preview cache, PNG export и передачи черновика в существующий Skin Manager.
- Avalonia headless UI: сетка проверена на ширине 900, 1060 и 1920, details — 900 и 1920;
  длинные названия, Back, Classic/Slim, legacy Classic и публичные Quick CSS selectors.
- Опубликованный Windows x64 Portable запущен на текущей Windows: responsive native
  window, встроенный .NET 10.0.12 и Skia, нормальное завершение с exit code 0.
- Installer собран; его установка/uninstall не выполнялись. Clean Windows VM,
  native DPI, системные pickers, внешние сайты и реальная Microsoft skin mutation
  остаются ручными проверками. Online catalog/API live tests не выполнялись.

Preview artifacts изолированы от ранее собранного релиза:
`.artifacts/releases/skin-catalog-preview/`. Версия остаётся `0.1.1-alpha`;
это сборка текущего рабочего дерева, без автоматической публикации/tag/commit.
