# Аккаунты NexLauncher

NexLauncher хранит Microsoft-аккаунты и локальные профили в одном списке. Тип отображается рядом с именем: **Microsoft** или **Локальный**. Выбранный аккаунт определяет имя и сессию, которые будут переданы Minecraft при следующем запуске.

## Локальный профиль

В **Настройках → Аккаунты** введи имя в поле локального профиля и нажми **Создать локальный аккаунт**. Профиль сразу появится в общем списке и станет активным. Сохранённый локальный профиль можно выбрать и использовать после перезапуска лаунчера без открытия Microsoft-входа.

Имя должно содержать **3–16 символов**: латинские буквы `A–Z`, `a–z`, цифры и `_`. Пробелы, дефисы и кириллица не допускаются; окружающие пробелы автоматически не удаляются. Например: `Steve`, `My_Player`, `Player123`.

Повторное создание имени с тем же регистром выбирает существующий профиль. `Player` и `player` являются разными локальными именами и получают разные UUID. UUID вычисляется совместимо с Java `UUID.nameUUIDFromBytes`, из строки `OfflinePlayer:<имя>` в UTF-8. Для одного и того же имени он остаётся одинаковым между запусками; случайный UUID на каждый вход не создаётся.

При запуске используется штатная offline session CmlLib с этим именем, стабильным UUID и явным локальным типом. Пароль и токены Microsoft не нужны. Создание, выбор, восстановление и удаление локального профиля не запускают OAuth и не обращаются к Microsoft-хранилищу. При инициализации общего списка лаунчер отдельно пробует загрузить сохранённые Microsoft-профили; ошибка их защищённого хранилища не мешает использовать локальные профили.

Локальный режим предназначен для одиночной игры и серверов, которые допускают локальные/offline-профили. Серверы с проверкой Microsoft (`online-mode=true`) требуют действительную Microsoft/Minecraft-сессию. Локальное имя не подтверждает владение Microsoft-аккаунтом и не подменяет его UUID или credentials.

**Локальный профиль не означает полностью автономную установку.** Получение каталога версий, установка Minecraft, библиотек, ресурсов и Java работают как раньше и могут требовать интернет. Существующий механизм проверки и восстановления файлов перед запуском также сохранён. Гарантия запуска установленной игры без каких-либо сетевых обращений в эту функцию не входит.

## Microsoft-аккаунт

Нажми **Войти через Microsoft**. Windows-версия использует штатный CmlLib OAuth через Edge WebView2 без собственного Client ID: Microsoft → Xbox → Minecraft → проверка доступа к Java Edition → профиль и сессия.

Перед запуском с Microsoft-аккаунтом выполняется штатное обновление сессии. Если требуется повторный интерактивный вход, лаунчер сообщает об этом. Ошибка Microsoft **не переключает незаметно на локальный режим**; локальный профиль выбирается пользователем явно.

Подробности входа, защиты токенов и ручных проверок: [MICROSOFT_AUTH.md](MICROSOFT_AUTH.md).

## Выбор и удаление

Выбери нужный профиль в общем списке и нажми **Использовать**. Имя и тип активного аккаунта отображаются в интерфейсе; выбор сохраняется между запусками. Microsoft и локальный профиль могут иметь одинаковое отображаемое имя, но остаются разными аккаунтами с разными идентификаторами.

Удаление убирает выбранный профиль только из NexLauncher на этом устройстве. Для Microsoft удаляются его локальные защищённые credentials; браузерная сессия WebView2 остаётся отдельной. У локального профиля удаляется сохранённое имя. Если удалён активный аккаунт, выбирается оставшийся доступный профиль; после удаления последнего активного аккаунта нет.

У локального профиля нет официального Microsoft skin URL: интерфейс использует стандартный резервный аватар с буквой имени. У Microsoft-профиля аватар загружается с официального `textures.minecraft.net`, если доступен.

При ошибке записи локального профиля интерфейс сохраняет предыдущий список и выбор. Незавершённое изменение не считается успешно сохранённым. Microsoft credentials и общий выбор находятся в двух разных файлах: если удаление Microsoft credentials уже сохранилось, а запись общего выбора затем завершилась ошибкой, удаление credentials не откатывается. Лаунчер показывает ошибку и обновляет список по фактическому состоянию; для возвращения удалённого Microsoft-профиля потребуется новый вход.

## Скин выбранного аккаунта

Нажми **Скин…** рядом с общим списком. Microsoft-скин загружается и меняется через
Minecraft Services; для второго сохранённого профиля активный аккаунт запуска
не переключается. Для Local можно импортировать PNG и сохранять модель/preview,
но **в самой игре Local Skin не заменяет стандартный скин**. Mods и JAR patches
не используются. Подробнее: [SKINS.md](SKINS.md).

## Хранение данных

На Windows папка данных обычно находится в `%LOCALAPPDATA%\NexLauncher`; точный путь показан в настройках.

| Файл | Содержимое | Защита |
| --- | --- | --- |
| `auth/profiles.json` | Версия формата, локальные имена и общий активный указатель `{ type, id }` | Обычный JSON: содержит только публичные данные, без сессий и токенов |
| `auth/accounts.dat` | Microsoft-профили, OAuth/Xbox/Minecraft credentials и внутренний выбор Microsoft-провайдера | Windows DPAPI `CurrentUser`; полностью зашифрован |
| `settings.json` | Сборки и настройки лаунчера, включая Quick CSS | Обычный JSON; аккаунтные credentials сюда не записываются |
| `skins/<hash>/skin.json` и managed PNG | Local Skin и модель, привязанные к type/ID | Локальные публичные данные; не отправляются в сеть |

`profiles.json` сохраняется через временный файл с последующей атомарной заменой. Допускается до 256 локальных профилей; размер файла ограничен 256 КиБ. UUID локального профиля вычисляется из имени при чтении; отдельное поле с произвольным UUID не сохраняется.

Старое защищённое Microsoft-хранилище продолжает использоваться; публичный список не является его копией и не содержит секретов. При первом запуске после обновления ранее выбранный Microsoft-аккаунт остаётся доступным через существующий провайдер.

Повреждённые файлы не перезаписываются автоматически. Если недоступен только Microsoft vault, лаунчер показывает предупреждение и сохраняет возможность выбрать локальный профиль. Если повреждён `profiles.json`, сначала сохрани его резервную копию и восстанови корректный файл; для осознанного сброса локального списка можно закрыть лаунчер и переименовать этот файл. Это не удаляет `accounts.dat`, игровые миры или сборки.

## Что проверить вручную

1. Создать локальный профиль, закрыть и снова открыть лаунчер: имя, UUID и активный выбор должны сохраниться.
2. Выбрать установленную сборку и запустить одиночную игру; проверить переданное имя.
3. Переключить Microsoft → локальный → Microsoft и проверить, что каждый запуск использует явно выбранный тип.
4. Проверить обычный Microsoft-вход и refresh, отмену входа и понятную ошибку истёкшей сессии.
5. Удалить один профиль, сохранив другой; после удаления последнего убедиться, что интерфейс предлагает создать или добавить аккаунт.
6. При необходимости проверить подключение к собственному серверу с разрешёнными локальными профилями. Сервер с Microsoft-проверкой должен по-прежнему требовать Microsoft-сессию.

Автоматические проверки используют временные папки и подставной Microsoft-провайдер; они проверяют формат имени, известный offline UUID, отсутствие OAuth/vault-вызовов в локальных операциях, сохранение, переключение, удаление и ошибки записи. Реальный Minecraft-процесс и внешние Microsoft API требуют отдельной ручной проверки.
